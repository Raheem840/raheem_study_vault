# Serial Communication — UART, I2C, SPI

## 1. Why "serial"? — the core idea
Serial communication sends data **one bit at a time** over a single wire (or pair), as opposed to **parallel** communication (many bits at once over many wires). Fewer wires = simpler, cheaper, and (counter-intuitively) can go faster over longer distances because parallel wires suffer more from signal skew — this is why almost all modern peripherals (including USB, Ethernet, SATA) are serial.

## 2. UART (Universal Asynchronous Receiver/Transmitter)
**Asynchronous** = no shared clock line; both sides must independently agree on the **baud rate** (bits per second, e.g. 115200) beforehand.
- Uses just 2 data wires: **TX** (transmit) and **RX** (receive), plus GND — always cross TX↔RX between two devices.
- Each byte is framed with a **start bit**, the data bits, an optional **parity bit** (error checking), and **stop bit(s)** — this framing is how the asynchronous receiver knows where each byte begins/ends without a shared clock.
- Point-to-point only (one device to one device) — can't have multiple devices sharing a simple UART bus without extra hardware (unlike I2C/SPI below).
```c
uart_config_t uart_config = {
    .baud_rate = 115200,
    .data_bits = UART_DATA_8_BITS,
    .parity = UART_PARITY_DISABLE,
    .stop_bits = UART_STOP_BITS_1,
};
uart_param_config(UART_NUM_1, &uart_config);
uart_write_bytes(UART_NUM_1, "Hello", 5);
```
> **Exam trap**: mismatched baud rate between two UART devices produces garbled/gibberish characters — it's the single most common UART bug, and it's purely a configuration mismatch, not a hardware fault.

## 3. I2C (Inter-Integrated Circuit)
**Synchronous, multi-device bus** using just 2 wires shared by ALL devices on the bus:
- **SCL** (Serial Clock) — a shared clock signal, generated by whichever device is the current "master"
- **SDA** (Serial Data) — the shared bidirectional data line
- Each device on the bus has a unique **7-bit (or 10-bit) address**; the master specifies which address it wants to talk to before sending/receiving data.
- Supports **multiple masters and multiple slaves** on the same two wires (careful arbitration handles simultaneous access).
- Requires **pull-up resistors** on SCL and SDA (the bus is "open-drain" — devices can only pull the line LOW, external resistors pull it back HIGH).
```c
i2c_master_write_read_device(bus_handle, DEVICE_ADDR, &reg, 1, data, len, timeout);
```
Typical use: connecting several sensors (e.g. a BME280 + an OLED display) to the same two pins, distinguished by address.

## 4. SPI (Serial Peripheral Interface)
**Synchronous, faster than I2C**, typically 4 wires:
- **SCLK** (clock, from master)
- **MOSI** (Master Out, Slave In)
- **MISO** (Master In, Slave Out)
- **CS/SS** (Chip Select — one **per slave device**, used to pick which device is "listening" right now)
- Unlike I2C's shared address scheme, SPI selects a specific slave by **physically driving its unique CS line LOW** — meaning more devices need more GPIO pins (one CS wire each), unlike I2C's shared 2-wire bus.
- Full-duplex (can send and receive simultaneously, unlike I2C's half-duplex turn-taking) and generally much faster than I2C — commonly used for displays, SD cards, flash memory.

## 5. UART vs I2C vs SPI — THE comparison table (guaranteed exam material)
| Feature | UART | I2C | SPI |
|---|---|---|---|
| Wires | 2 (TX, RX) | 2 (SCL, SDA) shared bus | 4+ (SCLK, MOSI, MISO, 1 CS per device) |
| Clock | None (asynchronous — needs matched baud rate) | Shared clock (synchronous) | Shared clock (synchronous) |
| Devices per bus | 1-to-1 only | Many (via unique addresses) | Many (via one CS pin each) |
| Speed | Moderate (limited by baud rate) | Moderate | Fast |
| Duplex | Full-duplex | Half-duplex | Full-duplex |
| Typical use | Debug console, GPS modules, simple point-to-point links | Multiple low-speed sensors sharing 2 pins | Displays, SD cards, high-speed peripherals |
