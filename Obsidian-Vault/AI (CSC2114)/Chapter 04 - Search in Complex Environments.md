# Ch.4 — Search in Complex Environments

## 1. Why this matters for the exam
Chapter 3 assumed you just need to FIND a path/sequence of actions. Chapter 4 asks: what if you only care about the final state (not the path)? What if actions have uncertain outcomes? What if you can't fully observe the state? Classic asks: **"trace hill-climbing / simulated annealing on a given landscape"**, **"explain why genetic algorithms use crossover and mutation"**, **"describe an AND-OR search tree for a nondeterministic problem"**, **"define a belief state."**

## 2. Local search — when you only care about the goal state, not how you got there
Unlike Ch.3's systematic search (which explores a tree/graph and remembers the whole path), **local search** algorithms keep track of just the **current state** and move to neighbouring states, without retaining a search tree. Ideal for problems like scheduling or circuit layout where the path is irrelevant, only the final configuration matters — and they use **very little memory** (constant, regardless of state space size).

### a) Hill-climbing
"Climb uphill" — repeatedly move to the best-valued neighbour of the current state; stop when no neighbour is better.
**Problems (very testable):**
- **Local maxima**: a peak lower than the global maximum, but with no better neighbour — the algorithm gets stuck.
- **Ridges**: a sequence of local maxima very difficult to navigate because the "uphill" direction isn't aligned with any single available move.
- **Plateaus**: a flat area where all neighbours have equal value — no clear uphill direction (can be a genuine local maximum or a "shoulder" that leads higher if you push through it).
**Variants**: *stochastic hill-climbing* (picks randomly among uphill moves, not always the steepest), *first-choice hill-climbing* (generates neighbours randomly until one is better, useful when a state has many neighbours), *random-restart hill-climbing* (if stuck, restart from a new random state — trivially complete given enough restarts, since a random state is eventually a solution's basin of attraction).

### b) Simulated annealing
Like hill-climbing, but instead of always picking the best move, it sometimes picks a **worse** move too — with a probability that starts high and decreases over time following a "temperature" schedule. This lets it escape local maxima early on (when temperature is high, it's more willing to accept worse moves) while converging toward hill-climbing-like behaviour as temperature drops toward zero. Named after the metallurgical process of slowly cooling metal to reach a low-energy crystalline state.
- If the schedule lowers temperature slowly enough, simulated annealing is guaranteed to find the global optimum with probability approaching 1 — though this can take impractically long in the worst case.

### c) Local beam search
Instead of tracking one current state, track **k states in parallel**. At each step, generate all successors of all k states, and keep only the best k overall (not the best k *per parent* — this is the key distinction from just running k independent hill-climbs). Information is shared across the k parallel searches, so the search can concentrate quickly on the most promising areas — but this can also mean the k states lose diversity and cluster in one region ("all in the same local maximum's neighbourhood"). **Stochastic beam search** adds randomness to which successors survive, improving diversity, analogous to natural selection.

### d) Genetic algorithms (GA)
A variant of stochastic beam search where states ("individuals") are represented as strings (often bit-strings, called **chromosomes**), and new states are generated by combining pairs of parent states rather than just modifying one:
- **Population**: the set of k current states/individuals.
- **Fitness function**: like an objective function — higher fitness = more likely to be selected to reproduce.
- **Selection**: pick parent pairs, biased toward higher fitness (e.g. proportional to fitness score).
- **Crossover**: combine two parent chromosomes at a random "crossover point," producing offspring that mix both parents' genetic material — this is GA's key mechanism for combining good partial solutions from different individuals.
- **Mutation**: randomly flip a small number of bits in offspring, to maintain diversity and allow escaping local optima that crossover alone couldn't reach.
> **Exam trap**: crossover works well specifically when the encoding is such that useful "building blocks" occupy short contiguous substrings — if the encoding is arbitrary/poorly chosen, crossover can just as easily destroy good partial solutions as combine them.

## 3. Search with nondeterministic actions
Real environments (per Ch.2's dimensions) can be **stochastic**: an action might not produce the expected result (e.g. a "vacuum" action might not fully clean, or a robot's wheels might slip). We now must plan for **all possible outcomes**, not just one.

### AND-OR search trees
- **OR nodes**: like normal search — the agent CHOOSES which action to take (only needs ONE branch to succeed).
- **AND nodes**: represent the environment's response — since the outcome is nondeterministic, the plan must work for **EVERY possible outcome** the environment might produce (must succeed on ALL branches).
A solution in an AND-OR tree isn't a simple sequence of actions but a **conditional plan** (a subtree): "if outcome A happens, do this; if outcome B happens, do that."

## 4. Search with partial observations
When the agent can't fully observe the current state, it must reason about a **belief state**: the SET of all states it considers possible given its percept history so far, rather than a single known state.
- **Sensorless (conformant) search**: the agent has NO sensors at all — it must find a sequence of actions that achieves the goal for every state in its (large) initial belief state, without any feedback along the way. Surprisingly, conformant plans often exist even without any sensing, because actions can sometimes "funnel" many possible states toward the same outcome (e.g. a robot that always moves toward a wall ends up against the wall regardless of exact starting position).
- **Contingency (partially observable) search**: the agent CAN sense some things during execution, so its plan can be conditional on what it perceives along the way — belief states are updated (narrowed) using new percepts, similar in spirit to the AND-OR structure above.
- The belief-state search space is a search over SETS of physical states — this can be exponentially larger than the original problem's state space, which is why it's computationally much harder than Ch.3's classical search.

## 5. Online search agents
Classical (offline) search computes a complete solution before acting at all. An **online search agent** interleaves computation and action — it must act before it has fully explored the environment, learning the environment's layout as it physically moves through it (can't "teleport" to try a state, must actually get there or backtrack).
- Necessary when the environment is **unknown** (the agent doesn't have a map/model in advance) — it must literally explore to discover the state space.
- **Online DFS** is a natural fit (only needs to remember how to backtrack along the path actually taken), but a naive version can revisit the same states repeatedly in the worst case; smarter variants remember what's been explored to avoid redundant backtracking.
- Key tradeoff: an online agent can get trapped in "dead ends" it can't undo (irreversible actions) — competitive online search analysis compares an online agent's total travel cost against the cost an agent WITH full prior knowledge would have paid, formalized as **competitive ratio**.
