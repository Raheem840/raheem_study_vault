DSA / Terminal Drills

No single semester course covers all of this end-to-end — CSC 2100/1204 gave you the foundation in Year I, but DSA fluency is what the MIT-level mastery arc actually rests on, and what technical interviews test directly. This runs in parallel to whatever semester you're in, touched daily, never fully "done."

Topic Mastery

How to Actually Run This

  • One problem, every single morning, before the 06:00 block ends — untimed at first, timed once a topic feels solid.
  • Interleave: never do 5 problems from the same topic back to back. Mix in whatever this week's rotation is (see Weekly Cadence in Daily Schedule).
  • All resources below are free — no paid subscriptions needed: NeetCode (YouTube, free roadmap), Visualgo.net (free algorithm visualizer), LeetCode free tier, GeeksforGeeks, and Harvard's CS50 (free, OpenCourseWare).
  • Log a DSA win in the terminal on Today whenever you close out a hard problem — it counts toward the streak same as coursework.
CSC 3118 (Project I, Y3S1) → CSC 3211 (Project II, Y3S2)

Final Project Lab

Project I is the concept paper/proposal stage; Project II is the full build, examined by a panel. They're graded on demonstrated technical depth, not on how polished the product looks. You already have five real ventures running — the trick is picking the narrowest technical slice of one of them that has a genuine, testable claim behind it, rather than trying to defend "I built an app." Both are fixed at an A target in the recommended plan — they're fully within your control (no surprise exam), so they're where the plan expects zero slippage.

What Makes a Project Examinable

A panel wants a specific, falsifiable technical claim you can test and defend — "this matching algorithm outperforms plain filtering on X metric," not "I built a platform for Y." Pick one idea above, narrow it to a single mechanism, and go deep on that mechanism rather than wide on features. Start the concept paper in the first weeks of Y3S1 — Project I's whole job is to force that narrowing before you've sunk months into the wrong scope.

Cognitive Toolkit

The Memory Lab

Dense material across five semesters will not stick through re-reading. It sticks through retrieval, spacing, and connection. Below is the general system, plus the specific technique assigned to each course inside its own page.

Spaced Repetition

Review a fact right when you're about to forget it. Free Anki — one deck per course, one card per fact. 10-15 min every morning.

Apply to: proof laws, protocol/port numbers, SQL syntax, algorithm complexities.

Active Recall

Close the book. Blank-paper recall of everything you remember, then check the gaps. Far stronger than re-reading.

Apply to: re-deriving A* from memory, re-writing the TCP handshake, redoing a normalization example blind.

Feynman Technique

Explain it out loud in plain language to a first-year. Every stumble is a gap.

Apply to: "what is 3NF", "why is a Turing machine undecidable for this problem".

Interleaving

Mix problem types within one session so you practice choosing the tool, not just executing one.

Apply to: DSA problem sets, AI search-algorithm sets, proof-technique sets.

Dual Coding

Pair every abstract concept with a hand-drawn diagram. Creates a second memory pathway independent of text.

Apply to: network stacks, ER diagrams, FSMs, circuit schematics.

Elaborative Interrogation

For every fact, force "why is this true, why does it matter here" instead of accepting it.

Apply to: "why 2's complement", "why Bayes' theorem instead of raw frequencies".

Chunking

Break long procedures into 3-5 named sub-steps so working memory holds steps, not raw details.

Apply to: the DB app dev lifecycle, the 7-layer network stack, CSP backtracking.

Procedural / Build Memory

Some knowledge only sticks through your hands. Wire it, query it, configure it — don't just read about it.

Apply to: Embedded builds, SQL mini-project, network lab configuration.

Your Daily Encoding Loop

  • Same day (encode): new content → hand-write a one-page summary in your own words, no copying slides.
  • +1 day (retrieve): blank-paper recall of yesterday's summary before reopening notes.
  • +3 days (interleave): mixed problem set across the week's 2-3 most recent topics.
  • +7 days (space): Anki pass + one spoken Feynman explanation.
  • Before any test: full timed retrieval practice simulating real conditions.

First Class War Room

Makerere grades on a 5.0-point scale (A=5.0, B+=4.5, B=4.0, C+=3.5, C=3.0, D+=2.5, D=2.0). Typical classification bands run roughly: First Class ≥ 4.40, Second Upper 3.60–4.39, Second Lower 2.80–3.59, Pass 2.00–2.79 — confirm the exact current cutoff with the CoCIS/Academic Registrar handbook, since these bands have shifted university-wide before.

The plan below is fixed, not a suggestion to idly explore. Every course across all 5 remaining semesters is set to a specific target grade chosen so the whole plan clears 4.40 with a real margin — worked out at roughly 4.51 final CGPA, about 0.11 above the First Class line. That margin exists so one rough patch doesn't sink the whole plan — it is not room to relax.

Why Four Courses Are Set to B+, Not A

The math needs an average of roughly 4.93 grade points across all 84 remaining credit units — essentially straight A's. Four low-stakes, pure-theory courses (marked SLACK below) are deliberately set to B+ instead, as the one place a dip is pre-approved rather than a surprise: Discrete Mathematics and Automata, Complexity & Computability (proof-heavy, no practical component), plus Cryptology and Coding Theory and Compiler Design (dense, unfamiliar theory). Every other course — especially the ones tied to Belt Intelligence, PropertyPal, the IV Sentinel, and NexFlow, where you already have a practical head start — is fixed at A. If you can pull any SLACK course up to A too, that's pure extra buffer, never subtract from it.
